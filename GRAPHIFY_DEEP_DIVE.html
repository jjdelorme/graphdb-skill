3.2 Semantic Clustering vs. Community Detection

This represents the most critical theoretical and operational divergence between the two architectures.

Leiden

Graphify: Topological Community Detection

Theory: Adopts the Leiden algorithm (an advancement over Louvain) from complex network analysis, optimizing graph modularity by identifying densely interconnected node groups.

Mechanism: Rather than embedding code into vector space, Graphify injects LLM-derived semantic edges (semantically_similar_to, mentions) from documents and transcripts directly into the structural graph. Leiden then clusters code nodes based on the combined topology.

Advantages (Pros)
  • Zero embedding API costs & zero token overhead for vector generation.
  • No vector database or vector index infrastructure required.
  • Fast, deterministic clustering directly on graph topology.
Limitations (Cons)
  • Functions in separate files that implement identical business logic (e.g. duplicated payment validators) will not cluster together unless they have direct structural edges or doc co-mentions.
K-Means++

GraphDB: Dense Vector RPG Intent Layer

Theory: Implements the Repository Planning Graph (RPG) framework (GRAPHDB_OVERVIEW.md), treating low-level code implementation and high-level architectural intent as distinct graph layers.

  1. Atomic Extraction: LLM generates domain-first "verb-object" descriptors (e.g., authenticate-user) and flags volatility (extractor.go).
  2. Vectorization: Encodes descriptors with gemini-embedding-001 (768d) (vertex.go).
  3. K-Means++ Clustering: Calculates domain count $K = \sqrt{N/5}$, seeds centroids with K-Means++, and converges (cluster_semantic.go).
  4. Hierarchical Naming: Creates Domain and Feature nodes in Neo4j with PARENT_OF and IMPLEMENTS edges.
Advantages (Pros)
  • Captures latent conceptual relationships even across disconnected legacy silos.
  • Creates a human-navigable, business-aligned domain hierarchy.
Limitations (Cons)
  • Requires LLM token budget and Google Cloud Vertex AI or custom embedding API credentials.

Graphify Analysis Tools

  • • God Node Identification: Employs degree centrality metrics to pinpoint major architectural hubs and bottlenecks.
  • • Confidence Tagging: Tags edges as EXTRACTED (hard AST truth) or INFERRED (LLM-derived with confidence score 0.0–1.0).
  • • Graph Report: Generates architectural summaries and open questions in GRAPH_REPORT.md.

GraphDB Modernization Suite (The Feathers Suite)

1. Contamination Analysis (neo4j_contamination.go):

Detects boundary functions touching I/O, UI, DB, or network (is_volatile: true) and propagates volatility upward through the CALLS graph:

$$\text{score} = \frac{1}{\text{distance} + 1}$$ $$\text{risk} = 0.4 \cdot \text{fan\_in} + 0.1 \cdot \text{fan\_out} + 3.0 \cdot \text{volatility\_score} + 0.4 \cdot \text{churn}$$
2. Structural Seams / Pinch Points (neo4j.go:657):

Pinpoints optimal locations for interface extraction and mocking, ranked by: $$\text{Internal Fan-In} \times \text{Volatile Fan-Out}$$

3. Semantic Seams / Divergence (neo4j_semantic_seams.go):

Measures pairwise cosine similarity of function embeddings within the same Class or File. Flags functions with similarity $< 0.5$ as Single Responsibility Principle (SRP) violations.

4. Impact & What-If Simulation (neo4j_whatif.go):

Simulates hypothetical node removals for Strangler Fig migrations, calculating severed edges and newly orphaned subsystems.

5. Git Churn & Co-Change (neo4j_history.go):

Mines git log to identify files frequently committed together, exposing hidden temporal coupling missed by static AST analysis.

Actionable Takeaways & Cross-Pollination Opportunities

What GraphDB Skill Can Learn from Graphify

Opportunities for multimodal expansion & zero-token efficiency

1 Multimodal Ingestion Pipeline (Pass 2 & 3 Concept)

Adding an optional multimodal ingestion step for Architecture Decision Records (ADRs), whiteboard photos, design PDFs, or transcribed design meetings to enrich the RPG intent layer.

2 Domain-Seeded Speech Transcription

Using extracted code symbols ("God Nodes" or RPG Domain/Feature names) as vocabulary bias for Whisper transcription ensures accurate legacy domain-term recognition in standup audio.

3 Leiden Community Detection as a Pre-Filter

Incorporate Leiden as a zero-token structural clustering pre-pass to pre-segment massive graphs before running LLM-based K-Means++ semantic clustering, reducing LLM costs on massive codebases.

4 Universal MCP Server Support

Exposing the graphdb Go binary as a standard Model Context Protocol (MCP) server over stdio and http alongside the Gemini skill to support Cursor, Claude Code, and VS Code.

5 Static Artifact Generation

Adding a command to bundle the visualizer into a standalone static HTML report (like graphify-out/graph.html) to easily share architectural snapshots across engineering teams without Neo4j.

What Graphify Can Learn from GraphDB Skill

Modernization analytics & enterprise-scale reliability

1 Risk Contamination & Volatility Propagation

Distinguishing pure business logic from I/O boundary functions and propagating volatility along call chains provides high-value refactoring guidance that raw degree centrality cannot match.

2 Structural & Semantic Seams (The Feathers Suite)

Incorporating Pinch Point analysis ($\text{Fan-In} \times \text{Volatile Fan-Out}$) and SRP divergence analysis guides developers on precisely where to insert mocks and interfaces.

3 What-If Impact Simulation

Simulating severed edges and orphaned nodes for planned deletions elevates Graphify from a descriptive knowledge graph to an active refactoring planner.

4 Git Churn & Co-Change Coupling

Mining Git history reveals hidden temporal dependencies between files that frequently change together despite lacking static AST connections.

5 Asynchronous Batching for Large Monoliths

Staging LLM prompts via cloud batch storage (GCS/S3) ensures robust execution for massive 50,000+ file enterprise codebases without hitting rate limits or timeouts.
